# Как написать тему

Инструкция для автора темы — человека или агента. Термины — в [GLOSSARY.md](../GLOSSARY.md).

## Где что лежит

| Что | Где |
| --- | --- |
| Оглавление и порядок изучения (единый источник) | [`.vitepress/toc.mjs`](../.vitepress/toc.mjs) |
| Шаблон темы | [`templates/topic.md`](../templates/topic.md) |
| Темы | `<раздел>/<тема>.md`, например `javascript/closures.md` |
| Главная страница сайта | [`index.md`](../index.md) |
| Конфиг сайта | [`.vitepress/config.mjs`](../.vitepress/config.mjs) |

Сайт собирается VitePress из тех же markdown-файлов. `README.md`, `GLOSSARY.md`, `AGENTS.md`, `docs/` и `templates/` в сайт не попадают.

## Добавить тему

1. Найдите тему в `.vitepress/toc.mjs` — путь файла `<dir>/<file>.md` уже задан там. Не придумывайте новый путь: sidebar, главная и README строятся из этого списка.
2. Скопируйте `templates/topic.md` в `<dir>/<file>.md` и заполните. `title` во frontmatter и заголовок `#` совпадают с названием в `toc.mjs`; `level` — `ядро` или `дополнительно` (по разделу).
3. Тема появляется в sidebar и становится ссылкой на главной **автоматически**, как только файл существует. Править конфиг не нужно.
4. Обновите README: `npm run readme` (отметит тему ✅ и пересчитает прогресс). Сборка на CI падает, если README устарел.
5. Проверьте сборку локально (см. ниже) и запушьте в `main`. Сайт при этом не обновляется — см. «Публикация».

Новая тема, которой нет в оглавлении, сначала добавляется в `toc.mjs` (это решение по оглавлению, а не по теме).

## Правила шаблона

Полностью — в решении [«Шаблон файла темы»](https://github.com/alexrehtide/learning/issues/2). Главное:

- Frontmatter — только `title` и `level`. Если в названии есть `: `, значение `title` берётся в одинарные кавычки (`title: 'Модули: ESM и CommonJS'`), иначе VitePress падает на разборе YAML.
- Сразу под заголовком — blockquote «**Коротко.**».
- Разделы ровно такие и в таком порядке: Теория → Примеры → Вопросы с интервью → Задачи → Источники.
- Врезки — только `> [!NOTE]`, `> [!TIP]`, `> [!WARNING]`. Врезка о пре-релизе указывает статус и дату сверки.
- Вопрос с интервью — `::: details <вопрос>` (заголовок простым текстом, без кода) с эталонным ответом внутри.
- Задача — `### N. <Название> · легко|средне|сложно`, условие, затем `::: details Решение и разбор`; последней строкой «Сложность: O(…)», где уместно.
- Объём ядра — 5–8 вопросов, 3–6 задач, 300–450 строк; «дополнительно» — 3–5 вопросов, 2–3 задачи.
- Источники — плоский список, первоисточники первыми.
- Текст на русском; код, идентификаторы и комментарии в коде — на английском.
- Markdown страницы VitePress компилирует как шаблон Vue: <code v-pre>{{ … }}</code> **в инлайн-коде и обычном тексте** становится интерполяцией (рендерится пустым, ломает сборку или выполняет выражение). Такие фрагменты пишите как `<code v-pre>{{ value }}</code>`; внутри fenced-блоков (```) экранировать не нужно.

## Ссылки между темами

- Только относительные ссылки на **существующие** файлы: `[Промисы](../javascript/promises.md)`. VitePress валит сборку на мёртвых ссылках — это и есть проверка.
- Ссылку на тему, которая ещё не написана, не ставьте: её добавит тикет, который напишет ту тему, или финальная вычитка.

## Проверить локально

```sh
npm ci             # once
npm run dev        # http://localhost:5173/learning/ with hot reload
npm run build      # the same build as CI; fails on dead links
npm run preview    # serve the built site
```

> На Windows запускайте команды из пути с заглавной буквой диска (`C:\…`, а не `c:\…`): иначе VitePress 1.6 падает при рендеринге с `Cannot read properties of undefined (reading 'imports')`. В CI (Linux) проблемы нет.

## Публикация

[`.github/workflows/deploy.yml`](../.github/workflows/deploy.yml) запускается только вручную: проверка README, сборка VitePress, деплой на GitHub Pages — https://alexrehtide.github.io/learning/. Пуш в `main` его не запускает.

Запускайте деплой, когда дописан раздел — запушена его последняя тема:

```sh
gh workflow run deploy.yml
```

Дожидаться результата не нужно: проверку сайта делает человек.
