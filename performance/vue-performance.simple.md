# Скорость Vue и Nuxt простым языком

> **Коротко.** Vue — инструмент для создания интерфейсов, Nuxt — надстройка над ним, которая собирает страницы на сервере. Интерфейс во Vue состоит из **компонентов** — самостоятельных блоков вроде строки таблицы или карточки товара. Когда меняются данные, Vue перерисовывает те компоненты, которые эти данные использовали. Работы меньше, если перерисовывается меньше компонентов и если Vue следит за меньшим объёмом данных. В Nuxt главная стоимость — загрузка и «оживление» страницы в браузере. Её снижают, передавая меньше данных и откладывая оживление того, что пользователь пока не видит.

## Аналогия

Представьте табло вылетов в аэропорту. Когда у одного рейса меняется выход на посадку, разумно обновить одну строку, а не перепечатывать всё табло. Ещё лучше, если в строке обновляется только номер выхода, а название авиакомпании, которое никогда не меняется, не трогают вовсе.

Теперь представьте, что табло привезли уже напечатанным, но кнопки на нём заработают, только когда техник проверит каждую строку. Если строк сотни, а пассажиру нужна одна, проще сначала включить строки, на которые смотрят, а остальные — когда до них дойдут.

## Что происходит на самом деле

### Откуда берётся работа

Каждый компонент запоминает, какие данные он прочитал при отрисовке. Когда данные меняются, Vue ставит в очередь перерисовку именно этих компонентов, сравнивает новый вариант со старым и меняет на странице только различия. Дочерний компонент перерисовывается, только если изменилось то, что ему передали. Вся перерисовка после одного изменения — один непрерывный кусок работы, разбить его нельзя (почему это важно — в [Отзывчивости страницы простым языком](./runtime.simple.md)). Поэтому есть два рычага: меньше компонентов перерисовывается и дешевле каждая перерисовка.

### Что Vue делает сам

Когда разработчик описывает интерфейс в привычном для Vue формате шаблона, Vue заранее разбирает его и помечает, какие части никогда не меняются. Неизменные части создаются один раз и при сравнении пропускаются, а для изменчивых записано, что именно в них может поменяться: текст, оформление или что-то ещё. Шаблон из 200 элементов с двумя изменчивыми местами сравнивается за две операции.

Эту помощь легко потерять. Если писать интерфейс без шаблонов, Vue не знает, что неизменно, и сравнивает всё. Отдельные приёмы в шаблоне заставляют дочерний компонент перерисовываться при каждом обновлении родителя, даже если ничего не изменилось.

### Что передают компоненту

Vue сравнивает переданное по принципу «тот же это предмет или другой», а не по содержимому. Если при каждой перерисовке родитель создаёт новый объект с теми же данными, ребёнок считает его изменением и тоже перерисовывается.

Главный приём — передавать ребёнку уже готовый ответ. В списке из 10 строк можно передать каждой строке номер выбранной строки, и тогда при смене выбора перерисуются все 10. А можно передать каждой строке «выбрана ли именно ты», и тогда перерисуются только две: та, что потеряла выделение, и та, что его получила.

Для редких случаев есть ручные средства: отрисовать блок один раз и больше не трогать или перерисовывать его, только когда изменились перечисленные значения. Если забыть что-то перечислить, блок перестанет обновляться, и это будет ошибка, а не ускорение.

### Меньше слежения

Vue умеет следить за каждым вложенным полем данных. Для таблицы на 50 тысяч строк это десятки тысяч обёрток и сотни тысяч связей, созданных при первой отрисовке. Если данные приходят с сервера и заменяются целиком, Vue велят следить только за заменой, а не за каждым полем. Объекты сторонних библиотек, например карты или графика, помечают как «не следить вовсе». А огромный список на странице дорог сам по себе, поэтому его виртуализируют: показывают только видимые строки.

Лишние компоненты тоже стоят денег: каждый дороже обычного элемента страницы. Сто строк по три вложенных компонента — это триста компонентов.

### Как ищут проблему

Расширение Vue DevTools показывает, какие компоненты перерисовываются на действие и почему. Финальные цифры снимают на рабочей версии сайта: версия для разработки заметно медленнее из-за дополнительных проверок.

### Nuxt: данные внутри страницы

При сборке на сервере страница приходит готовой, а браузер затем **оживляет** её — гидрирует: выполняет тот же код и привязывает его к готовой разметке. Чтобы браузер не запрашивал данные второй раз, Nuxt вкладывает их прямо в страницу. Каждый лишний килобайт этих данных замедляет загрузку и оживление. Поэтому:

- из ответа сервера оставляют только поля, которые реально показываются;
- персональные блоки, не нужные поисковикам (например, рекомендации), запрашивают уже в браузере, и они не попадают в страницу;
- страницу можно показать сразу, не дожидаясь данных, с индикатором загрузки.

### Nuxt: отложенное оживление

- **Ленивые компоненты** выделяются в отдельную часть кода и грузятся, только когда понадобились.
- **Отложенное оживление**: разметка блока видна сразу, а его код грузится и выполняется позже — когда блок попал на экран, когда браузер свободен, при первом взаимодействии. Первый клик при этом не теряется. Блоки первого экрана так не откладывают: пользователь нажмёт на неживую кнопку.
- **Серверные компоненты** собираются только на сервере, и их код вообще не попадает в браузер. Подходит, например, для разметки статьи с подсветкой кода.
- **Кэш на сервере** позволяет не собирать страницу заново на каждый запрос (подробнее — в [Кэшировании простым языком](../network/caching.simple.md)).

В следующей версии Vue готовится режим без сравнения вариантов: каждое изменчивое место обновляется напрямую. Пока он не вышел в стабильной версии.

## Что может пойти не так

- Родитель передаёт детям новые объекты и функции при каждой перерисовке, и перерисовывается весь список.
- Vue следит за каждым полем огромной таблицы, хотя её заменяют целиком.
- В страницу вложены все данные ответа сервера, хотя показывается три поля.
- Отложили оживление блока первого экрана, и кнопки не отвечают.
- Замеры сделаны на версии для разработки.

## Как делают правильно

- Передают компонентам готовые ответы и не создают новые объекты без нужды.
- Большие данные хранят так, чтобы Vue следил только за их заменой.
- Урезают данные до показываемых полей, персональное грузят в браузере.
- Блоки ниже первого экрана делают ленивыми и оживляют при появлении на экране.
- Проверяют, какие компоненты перерисовываются, и мерят на рабочей версии.

## Что запомнить

- Во Vue перерисовывается компонент, поэтому важно, сколько компонентов затронуто.
- Новый объект с тем же содержимым Vue считает изменением.
- Чем меньше данных под наблюдением, тем дешевле.
- В Nuxt дороже всего загрузка и оживление: меньше данных в странице, позже оживление невидимого.
