# Темы простым языком для раздела

Правила формата — единственный источник истины: раздел «Тема простым языком» в [docs/authoring.md](../../../docs/authoring.md) и термин в [GLOSSARY.md](../../../GLOSSARY.md). Они утверждены пользователем: применяй их как есть, не пересогласовывай. Новый термин или решение по формату — через навык `domain-modeling`.

Называй результат «тема простым языком» — в ответах, коммитах и файлах.

## Шаги

1. **Собери список.** Темы раздела — все `<раздел>/*.md`, у которых ещё нет пары `.simple.md`. Пиши их все сразу, без пилота. Готово, когда список согласован с пользователем, если раздел он не назвал явно.

2. **Прочитай образцы.** Два-три готовых `*/*.simple.md` (например, `security/` и `network/`) — по ним сверяй тон, объём и скелет.

3. **Прочитай исходники.** Из каждой темы — только «Теорию» и «Примеры», всё до `## Вопросы с интервью`:

   ```sh
   awk '/^## Вопросы с интервью/{exit} {print}' <раздел>/<тема>.md
   ```

   Каждое утверждение простой темы должно опираться на прочитанное: новых фактов не добавляй.

4. **Напиши файлы** `<раздел>/<тема>.simple.md` по правилам authoring.md. Ссылки на исходную тему ставь только с простой темы на техническую, в одну сторону — исходная тема остаётся без видимой ссылки на простую. Связывай простые темы между собой: внутри раздела и с уже готовыми из других разделов (`../security/xss.simple.md`). Если в готовых простых темах есть упоминания понятий из нового раздела без ссылки — добавь туда ссылки на новые файлы. Конфиг (`toc.mjs`, `.vitepress/`) остаётся как есть: жест и список пар (`.vitepress/theme/plain.data.mjs`) подхватывают новые файлы сами. Готово, когда для каждой темы из шага 1 есть файл и каждый прошёл чек-лист authoring.md: frontmatter, скелет, 60–120 строк, без кода, термины объяснены.

5. **Проверь сборку.** Из PowerShell, с путём `C:\Users\alex\work\learning` (заглавная `C:`):

   ```powershell
   npm run build        # падает на мёртвых ссылках — это и есть проверка ссылок
   npm run readme:check # должен быть up to date: простые темы не влияют на README
   ```

   Затем в Bash:

   ```sh
   # простая тема не попала в поиск: для уникальной фразы из каждого нового файла — 0
   grep -c '<фраза>' .vitepress/dist/assets/chunks/@localSearchIndexroot*.js
   # новые пары попали в бандл жеста: в выводе есть каждый новый путь
   grep -o '"<раздел>/[a-z-]*"' .vitepress/dist/assets/chunks/theme*.js
   ```

   Готово, когда сборка зелёная, README up to date, каждая проверочная фраза даёт `0` и каждый новый путь есть в бандле. Сам жест повторно в браузере не проверяй — механизм не менялся.

6. **Закоммить и запушь.** Один коммит на весь раздел, файлы добавляй явно по путям (временные файлы вроде `HANDOFF.md` в коммит не входят). Сообщение — `Add plain-language versions of the <section> topics` с attribution-строкой из system-reminder. Пуш в `main`. Деплой запускает пользователь: сообщи, что раздел готов к `gh workflow run deploy.yml`, и оставь запуск ему.

## Открытый вопрос

Работает ли прямая загрузка `…/<тема>.simple` (точка в имени) на GitHub Pages, пользователь проверяет после деплоя. Если всплывёт проблема — опиши её пользователю и дождись решения: она затрагивает все разделы сразу.
