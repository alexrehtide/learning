# Деревья и графы: BFS и DFS

> **Коротко.** Граф — вершины и рёбра. Дерево — связный граф без циклов. Во фронтенде графы обычно разреженные, поэтому их хранят списком смежности (`Map` вершина → соседи), а деревья — объектами с `children`. Обход в глубину (DFS) идёт по стеку, явному или стеку вызовов. Обход в ширину (BFS) идёт по очереди и в невзвешенном графе находит кратчайший путь. Оба обхода стоят O(V + E). На DFS построены обнаружение циклов и топологическая сортировка: порядок сборки и выполнение ES-модулей. Рекурсивный обход глубоких данных падает с `RangeError`, поэтому на интервью ждут итеративную версию.

**Связанные темы:** [Оценка сложности](./complexity.md), [Стеки и очереди](./stacks-and-queues.md), [Сортировки и бинарный поиск](./sorting-and-searching.md), [Массивы, строки и хеш-таблицы](./arrays-strings-hashing.md), [DOM API и observers](../browser/dom.md), [Модули: ESM и CommonJS](../javascript/modules.md), [Итераторы и генераторы](../javascript/iterators-and-generators.md), [Память и сборка мусора](../javascript/memory-and-gc.md), [Рекурсия и динамическое программирование](./recursion-and-dp.md)

## Теория

### Термины и представление

**Граф** (graph) G = (V, E) — множество вершин V и рёбер E. Рёбра бывают ориентированными (зависимость «`a` импортирует `b`») и неориентированными (дружба), со весом и без. **Дерево** (tree) — связный граф без циклов: у него ровно V − 1 рёбер и между любыми двумя вершинами ровно один путь. У **корневого** дерева есть корень, у каждой вершины, кроме корня, — один родитель. Глубина узла — число рёбер до корня, высота дерева — наибольшая глубина. **Двоичное** (binary) дерево — не больше двух детей, `left` и `right`.

| Представление | Память | Соседи вершины | Есть ли ребро u → v | Когда |
| --- | --- | --- | --- | --- |
| Объекты-узлы `{ value, children }` | O(V) | O(deg) | O(deg) | деревья: DOM, VDOM, меню, комментарии |
| Список смежности `Map<V, V[]>` | O(V + E) | O(deg) | O(deg), с `Set` — O(1) в среднем | разреженные графы — почти все во фронтенде |
| Матрица смежности V × V | O(V²) | O(V) | O(1) | плотные графы, маленькие V, сетки |
| Список рёбер `[u, v][]` | O(E) | O(E) | O(E) | формат ввода: из него строят список смежности |

Граф модулей, зависимостей пакетов или ссылок между страницами разрежен: E порядка V, а не V². Матрица на 10 000 вершин — 10⁸ ячеек, список смежности — десятки тысяч записей. Сетка (лабиринт, игровое поле, пиксели) — граф, который не хранят вовсе: соседи клетки `(r, c)` вычисляются на лету.

> [!TIP]
> Ключи-вершины удобнее держать в `Map`, а не в объекте: вершиной может быть объект или DOM-узел, а строковые id вроде `'constructor'` не столкнутся с прототипом ([подробнее](./arrays-strings-hashing.md)).

### Обход в глубину (DFS)

DFS (depth-first search) идёт по одной ветке до конца и только потом возвращается. Рекурсивная версия использует стек вызовов, итеративная — массив-стек ([подробнее](./stacks-and-queues.md)). В графе нужно множество `visited`: без него цикл `a → b → a` зациклит обход, а ромб `a → b, a → c, b → d, c → d` обойдёт `d` дважды. В дереве без ссылок на родителя `visited` не нужен.

Каждая вершина посещается один раз, каждое ребро просматривается один раз (в неориентированном — дважды). Отсюда **O(V + E)** времени и O(V) памяти на `visited` и стек. Для дерева E = V − 1, то есть O(n).

Порядок обработки узла относительно детей даёт три обхода:

- **pre-order** — узел, потом дети. Копирование и сериализация дерева, печать оглавления, `querySelectorAll` (порядок документа — это pre-order).
- **post-order** — дети, потом узел. Всё, где ответ узла зависит от ответов детей: размер поддерева, высота, удаление дерева, вычисление выражения. Зависимости раньше зависящих — тоже post-order.
- **in-order** — левое поддерево, узел, правое. Только для двоичных деревьев, у дерева поиска даёт отсортированную последовательность.

Итеративный pre-order прост: снять узел, обработать, положить детей в обратном порядке. Итеративный post-order сложнее: узел нужно обработать после детей, а снят он со стека раньше. Есть два приёма. Первый — класть узел дважды с флагом «дети уже в стеке». Второй — сделать pre-order в порядке «узел, правый, левый» и перевернуть результат, но это O(n) памяти под результат.

### Обход в ширину (BFS)

BFS (breadth-first search) обходит вершины слоями: сначала все на расстоянии 1, потом 2 и так далее. Нужна FIFO-очередь. В JS это массив с указателем головы, а не `shift`: на больших графах `shift` превращает O(V + E) в квадратичный обход ([подробнее](./stacks-and-queues.md)).

**Почему BFS находит кратчайший путь.** Вершины выходят из очереди в порядке неубывания расстояния: все вершины слоя k попадают в очередь раньше любой вершины слоя k + 1. Поэтому первый раз, когда BFS достиг вершины, он пришёл по пути с наименьшим числом рёбер. Чтобы восстановить сам путь, при постановке в очередь запоминают родителя (`prev.set(next, node)`) и потом идут по `prev` от цели к старту.

Это верно только для **невзвешенного** графа. Если у рёбер разный вес, путь из трёх лёгких рёбер может быть короче пути из одного тяжёлого. Тогда нужен алгоритм Дейкстры: та же схема, но вместо очереди — приоритетная очередь по расстоянию, O((V + E) log V) с бинарной кучей. Для весов 0 и 1 хватает дека: рёбра веса 0 кладутся в голову, веса 1 — в хвост (0-1 BFS, O(V + E)).

**Метить при постановке, а не при извлечении.** Если отмечать вершину в `visited` только при извлечении, её успеют поставить в очередь все соседи, и очередь разрастётся до O(E) записей с повторами. Результат при этом не меняется, но тратятся время и память.

**Память.** BFS держит в очереди целый слой — O(ширина). DFS держит путь от корня — O(глубина). Для широкого неглубокого дерева (файловая система, оргструктура) DFS экономнее. Для глубокого узкого (длинная цепочка ответов) экономнее BFS.

### Глубина рекурсии

Рекурсивный DFS короче, но его глубина равна высоте дерева, а стек вызовов мал ([подробнее](./complexity.md)). Данные, у которых глубину задаёт пользователь или сервер, — ветки комментариев, вложенный JSON, сгенерированный DOM, связный список — рано или поздно превысят предел.

> [!WARNING]
> Замер в Node 26 (V8 14.6), цепочка `{ children: [child] }`: рекурсивный подсчёт узлов с `for…of` по детям падает с `RangeError: Maximum call stack size exceeded` на глубине около 5 560, с циклом по индексу — около 8 690, рекурсия по связному списку — около 11 000. `for…of` создаёт итератор и утяжеляет кадр. Предел задан в байтах стека, поэтому в браузере и на другой платформе цифры будут другими. Итеративный обход на массиве ограничен только памятью.

Тот же предел есть у рекурсивных **генераторов**. Обход `function* walk(n) { yield n; for (const c of n.children) yield* walk(c) }` красив, но каждое значение из глубины h проходит через h делегирующих генераторов. Получается O(n · h): на цепочке из 2000 узлов в Node 26 — около 80 мс против 0,1 мс у генератора с явным стеком ([подробнее](../javascript/iterators-and-generators.md)).

Во Vue та же ловушка в `deep`-watch. `traverse` в `@vue/reactivity` 3.5.45 — рекурсивный DFS по объектам, массивам, `Map`, `Set` и `ref`. Против циклов у него `seen: Map<объект, оставшаяся глубина>`: объект пропускается, если его уже обошли с не меньшим запасом глубины. Циклическое состояние (`a.self = a`) поэтому не зависает, а `deep: 2` (числовая глубина появилась в 3.5) может пройти один объект дважды по путям разной длины. Но глубокое дерево рекурсия не переживает: `watch(reactive({ root }), cb, { deep: true })` на цепочке из 2000 уровней `{ children: [...] }` в Node 26 падает с `RangeError` уже при создании наблюдателя.

### Циклы и топологическая сортировка

**Цикл в ориентированном графе** ищут DFS с тремя состояниями вершины: белая — не посещена, серая — в текущем пути (на стеке), чёрная — обработана целиком. Ребро в серую вершину — **обратное** ребро: оно ведёт в предка на текущем пути, значит, есть цикл. Ребро в чёрную вершину циклом не является: это ромб, а не петля. Двух состояний (`visited`) недостаточно: на ромбе `a → b → d`, `a → c → d` второй заход в `d` выглядит как цикл, хотя его нет.

В **неориентированном** графе ребро ведёт в обе стороны, поэтому возврат к родителю по тому же ребру — не цикл. Цикл есть, если DFS встретил посещённую вершину, которая не родитель текущей. Другой способ — система непересекающихся множеств (union-find): ребро между вершинами одного множества замыкает цикл.

**Топологическая сортировка** (topological sort) упорядочивает вершины так, что каждое ребро u → v идёт слева направо: зависимость раньше зависящего. Она существует тогда и только тогда, когда в графе нет циклов (DAG, directed acyclic graph). Два алгоритма, оба O(V + E):

1. **Кан** (Kahn). Посчитать входящие степени. Очередь начинается с вершин без входящих рёбер. Извлечённая вершина уходит в ответ, у её соседей степень уменьшается, обнулившиеся встают в очередь. Если в ответ попало меньше V вершин, остаток содержит цикл. Бонус: вершины одного «слоя» независимы, их можно собирать параллельно.
2. **DFS**. Вершина добавляется в список, когда она стала чёрной (post-order). Перевёрнутый post-order — топологический порядок. Серая вершина на пути — цикл.

Где это во фронтенде: порядок сборки пакетов в монорепозитории (`dependsOn` в Turborepo и Nx), порядок выполнения ES-модулей, пересчёт ячеек таблицы, порядок миграций, порядок инициализации плагинов с зависимостями.

**ES-модули** — пример из спецификации. `InnerModuleLinking` и `InnerModuleEvaluation` обходят граф модулей рекурсивным DFS, и модуль выполняется после своих зависимостей, то есть в post-order ([подробнее](../javascript/modules.md)). Статус `evaluating` — это серая вершина, `evaluated` — чёрная. Циклы импортов спецификация не запрещает. Поле `[[DFSAncestorIndex]]` и стек модулей находят **компоненты сильной связности** (SCC) по схеме алгоритма Тарьяна. Все модули одного цикла переходят в `linked` и `evaluated` вместе, а внутри цикла порядок определяет точка входа в обход. Поэтому при циклическом импорте одна из сторон видит ещё не инициализированные привязки.

### DOM как дерево

DOM — корневое дерево узлов, и все обходы выше к нему применимы. Две пары API — «по узлам» (`childNodes`, `firstChild`, `nextSibling`) и «по элементам» (`children`, `firstElementChild`, `nextElementSibling`) — различаются тем, видят ли они текст и комментарии ([подробнее](../browser/dom.md)). Ссылки `parentNode` позволяют подниматься вверх без стека.

- **`querySelectorAll`** — статический список в порядке документа (pre-order). Удобен, когда условие выражается селектором.
- **`TreeWalker`** (`document.createTreeWalker(root, whatToShow, filter)`) — курсор по поддереву с методами `nextNode`, `parentNode`, `firstChild`, `nextSibling`. Маска `whatToShow` выбирает типы узлов: `NodeFilter.SHOW_TEXT` — единственный стандартный способ перебрать все текстовые узлы (подсветка результатов поиска, подсчёт слов). Фильтр возвращает `FILTER_ACCEPT`, `FILTER_SKIP` (пропустить узел, но зайти в детей) или `FILTER_REJECT` (пропустить вместе с поддеревом). Обход без рекурсии, глубина не ограничена.
- **`contains`** — является ли узел потомком (включая сам узел). **`compareDocumentPosition`** — битовая маска: раньше или позже в документе, предок, потомок, другое дерево. **`closest(selector)`** — ближайший предок, подходящий под селектор.

> [!WARNING]
> `FILTER_REJECT` отсекает поддерево только в `TreeWalker`. В `NodeIterator` спецификация DOM трактует его как `FILTER_SKIP`, и потомки отвергнутого узла попадают в обход (проверено в jsdom). Ещё отличие: `NodeIterator.nextNode()` первым возвращает сам корень, а `TreeWalker.nextNode()` начинает с его первого потомка.

Обычные обходы не заходят в **shadow DOM**: `children` хоста — это light DOM, а теневое дерево доступно через `element.shadowRoot`, и только если оно открытое.

### Деревья в данных фронтенда

Сервер часто отдаёт дерево **плоским списком** со ссылкой на родителя: категории, комментарии, меню, файлы (`{ id, parentId }`). Сборка вложенного дерева — O(n) с `Map` по `id` (задача 2). Обратное преобразование — DFS с глубиной в каждом узле — даёт плоский список для отрисовки дерева виртуальным списком: строк столько, сколько раскрытых узлов, а отступ берётся из глубины.

### Двоичное дерево поиска (BST)

Инвариант **BST** (binary search tree): все ключи левого поддерева меньше ключа узла, все ключи правого — больше. Именно **всего поддерева**, а не только прямых детей: это самая частая ошибка в задаче «проверить, что дерево — BST». In-order обход BST выдаёт ключи по возрастанию.

Поиск, вставка и удаление идут от корня вниз — O(h). У сбалансированного дерева h = O(log n), но обычный BST не балансируется сам. Вставка уже отсортированных ключей вырождает его в список, и операции становятся O(n). Гарантию O(log n) дают самобалансирующиеся деревья: AVL, красно-чёрные (на них устроены `TreeMap` в Java и `std::map` в C++), B-деревья в базах данных.

В JS упорядоченной коллекции нет: `Map` хранит порядок вставки, а не порядок ключей. Для «ближайшего ключа не больше x» и диапазонных запросов берут отсортированный массив с бинарным поиском, если вставок мало ([подробнее](./sorting-and-searching.md)), кучу, если нужен только минимум ([подробнее](./stacks-and-queues.md)), или библиотеку с деревом.

## Примеры

```js
// Adjacency list from an edge list; vertices can be any values, including objects
function buildGraph(edges, directed = true) {
  const graph = new Map();
  const add = (u, v) => {
    if (!graph.has(u)) graph.set(u, []);
    graph.get(u).push(v);
  };
  for (const [u, v] of edges) {
    add(u, v);
    if (directed) { if (!graph.has(v)) graph.set(v, []); } else add(v, u);
  }
  return graph;
}

// Iterative DFS: visit order from `start`, no call stack limit
function dfs(graph, start) {
  const visited = new Set();
  const order = [];
  const stack = [start];
  while (stack.length) {
    const node = stack.pop();
    if (visited.has(node)) continue; // a node may be pushed several times
    visited.add(node);
    order.push(node);
    const next = graph.get(node) ?? [];
    for (let i = next.length - 1; i >= 0; i--) {
      if (!visited.has(next[i])) stack.push(next[i]);
    }
  }
  return order;
}

// BFS shortest path in an unweighted graph: O(V + E)
function shortestPath(graph, start, goal) {
  const prev = new Map([[start, null]]); // doubles as `visited`
  const queue = [start];
  for (let head = 0; head < queue.length; head++) {
    const node = queue[head];
    if (node === goal) {
      const path = [];
      for (let n = goal; n !== null; n = prev.get(n)) path.push(n);
      return path.reverse();
    }
    for (const next of graph.get(node) ?? []) {
      if (!prev.has(next)) { // mark on enqueue, not on dequeue
        prev.set(next, node);
        queue.push(next);
      }
    }
  }
  return null; // unreachable
}
```

```js
// Level-order traversal: one array per level
function levels(root) {
  const result = [];
  let level = root ? [root] : [];
  while (level.length) {
    result.push(level.map((n) => n.value));
    level = level.flatMap((n) => n.children);
  }
  return result;
}

// Iterative post-order: children before the node, e.g. to compute subtree sizes
function subtreeSizes(root) {
  const size = new Map();
  const stack = [[root, false]];
  while (stack.length) {
    const [node, expanded] = stack.pop();
    if (expanded) {
      size.set(node, 1 + node.children.reduce((s, c) => s + size.get(c), 0));
    } else {
      stack.push([node, true]); // revisit after the children
      for (const child of node.children) stack.push([child, false]);
    }
  }
  return size;
}
```

```js
// All text nodes under `root` except those inside <script>/<style>
function textNodes(root) {
  const walker = document.createTreeWalker(root, NodeFilter.SHOW_ELEMENT | NodeFilter.SHOW_TEXT, {
    acceptNode(node) {
      if (node.nodeType === Node.TEXT_NODE) return NodeFilter.FILTER_ACCEPT;
      return node.matches('script, style')
        ? NodeFilter.FILTER_REJECT // skip the whole subtree
        : NodeFilter.FILTER_SKIP; // skip the element itself, visit its children
    },
  });
  const result = [];
  while (walker.nextNode()) result.push(walker.currentNode);
  return result;
}
```

## Вопросы с интервью

::: details Чем BFS отличается от DFS и как выбрать между ними
BFS идёт слоями по очереди, DFS — по ветке до конца по стеку. Оба посещают каждую вершину и ребро один раз: O(V + E). BFS выбирают, когда важно расстояние: кратчайший путь в невзвешенном графе, «ближайший подходящий узел», обход по уровням, распространение от нескольких источников. DFS — когда важна структура пути: циклы, топологическая сортировка, компоненты связности, перебор с возвратом, post-order вычисления по дереву. По памяти BFS держит слой (O(ширина)), DFS — путь (O(глубина)). Если подходят оба, DFS проще написать, но рекурсивный упирается в стек вызовов, поэтому на глубоких данных пишут итеративный.
:::

::: details Почему BFS находит кратчайший путь и когда этого недостаточно
Очередь выдаёт вершины в порядке неубывания расстояния: слой k целиком в очереди раньше любой вершины слоя k + 1. Поэтому первое достижение вершины — путь с наименьшим числом рёбер. Для восстановления пути при постановке в очередь запоминают родителя. Если у рёбер веса, «меньше рёбер» не значит «короче»: нужен Дейкстра с приоритетной очередью, O((V + E) log V), при отрицательных весах — Беллман — Форд. Для весов 0 и 1 хватает 0-1 BFS на деке. DFS кратчайший путь не находит вовсе: первый найденный путь зависит от порядка соседей.
:::

::: details Почему в BFS вершину помечают при постановке в очередь, а не при извлечении
Пока вершина ждёт в очереди, до неё могут дойти другие соседи. Если `visited` ставится только при извлечении, каждый из них снова поставит её в очередь. Ответ останется верным, потому что первое извлечение всё равно придёт по кратчайшему пути. Но очередь вырастет до O(E) записей с повторами, а на плотном графе или сетке это кратно больше по времени и памяти. При постановке в очередь каждая вершина попадает в неё ровно один раз. У итеративного DFS обратная ситуация: отметка при извлечении нужна, чтобы порядок совпадал с рекурсивным, а дубликаты в стеке отсекает проверка после `pop`.
:::

::: details Как найти цикл в ориентированном графе и чем это отличается от неориентированного
В ориентированном — DFS с тремя цветами: белая вершина не посещена, серая на текущем пути, чёрная завершена. Ребро в серую вершину ведёт к предку на пути — это цикл. Ребро в чёрную — нет: так выглядит ромб `a → b → d`, `a → c → d`, и простой `visited` ошибочно принял бы его за цикл. Альтернатива — алгоритм Кана: если топологическая сортировка обработала не все вершины, оставшиеся лежат на цикле или за ним. В неориентированном графе каждое ребро двустороннее, поэтому возврат к родителю — не цикл. Цикл — встреча с посещённой вершиной, которая не родитель. Ещё вариант — union-find: ребро внутри одного множества замыкает цикл.
:::

::: details Что такое топологическая сортировка и где она встречается во фронтенде
Это порядок вершин ориентированного графа, в котором каждое ребро идёт от более ранней к более поздней: зависимости раньше зависящих. Существует только у графа без циклов. Алгоритм Кана снимает вершины с нулевой входящей степенью через очередь и заодно находит цикл и группы для параллельного выполнения. DFS-вариант — перевёрнутый post-order. Оба O(V + E). Примеры: порядок сборки пакетов монорепозитория (`dependsOn` в Turborepo и Nx), выполнение ES-модулей (спецификация обходит граф DFS-ом, модуль выполняется после зависимостей, а циклы склеивает в компоненты сильной связности через `[[DFSAncestorIndex]]`), пересчёт формул в таблице, порядок миграций.
:::

::: details Когда рекурсивный обход опасен и как переписать его на явный стек
Когда глубину задают данные: ветки комментариев, вложенный JSON, связный список, сгенерированный DOM. Стек вызовов ограничен в байтах: в Node 26 рекурсия по дереву или списку падает на глубине 5–11 тысяч в зависимости от размера кадра. Хвостовые вызовы V8 не оптимизирует. Pre-order переписывается просто: массив-стек, дети кладутся в обратном порядке. Для post-order узел кладут дважды с флагом «дети уже в стеке». Рекурсивные генераторы с `yield*` вдобавок стоят O(n · h): каждое значение поднимается через всю цепочку делегирования. Во Vue `deep`-watch тоже рекурсивный и на дереве из ~2000 уровней падает при создании наблюдателя.
:::

::: details Как обойти DOM и что выбрать: рекурсию, TreeWalker или querySelectorAll
Если условие выражается селектором, `querySelectorAll`: нативный обход в порядке документа и статический результат. Если нужны текстовые узлы или сложная логика отсечения, `TreeWalker`: курсор без рекурсии, маска `whatToShow` и фильтр, где `FILTER_REJECT` пропускает всё поддерево (в `NodeIterator` — нет, там это `FILTER_SKIP`). Рекурсия по `children` уместна для небольших деревьев и для вычислений post-order. `children` видит только элементы, `childNodes` — ещё текст и комментарии. Обходы не заходят в shadow DOM: открытое теневое дерево доступно через `shadowRoot`. Для отношений между узлами есть готовые методы: `contains`, `closest`, `compareDocumentPosition`.
:::

::: details Что гарантирует двоичное дерево поиска и почему O(log n) не гарантировано
Инвариант — все ключи левого поддерева меньше узла, правого — больше. Поэтому поиск идёт по одной ветке, а in-order обход выдаёт ключи отсортированными. Все операции стоят O(h), где h — высота. Обычный BST не балансируется: вставка отсортированных данных вырождает его в список с h = n. O(log n) гарантируют AVL- и красно-чёрные деревья, на которых сделаны `TreeMap` и `std::map`. В JS упорядоченной коллекции нет, поэтому её заменяют отсортированным массивом с бинарным поиском, кучей (если нужен только минимум) или библиотекой. Типичная ошибка в задаче «проверить BST» — сравнивать узел только с детьми, а не передавать вниз допустимый диапазон.
:::

## Задачи

### 1. Ближайший общий предок двух DOM-узлов · легко

Напишите `commonAncestor(a, b)` — ближайший узел, который содержит и `a`, и `b` (узел содержит сам себя). Если узлы в разных деревьях, верните `null`.

::: details Решение и разбор
Предки `a` собираются в `Set`, затем от `b` идём вверх до первого узла из множества.

```js
function commonAncestor(a, b) {
  const ancestors = new Set();
  for (let n = a; n; n = n.parentNode) ancestors.add(n);
  for (let n = b; n; n = n.parentNode) if (ancestors.has(n)) return n;
  return null;
}
```

Вариант с O(1) памяти: посчитать глубины, поднять более глубокий узел на разницу, затем поднимать оба по шагу до совпадения. Вариант с `contains`: идти от `a` вверх, пока `n.contains(b)` ложно. Это короче, но `contains` сам O(глубина), так что в худшем случае O(h²). Готовый API — `Range.commonAncestorContainer`, но с ловушкой. Если `setEnd` получает точку раньше начала, диапазон схлопывается в неё, и предком окажется сам второй узел (проверено в jsdom). Узлы сначала упорядочивают через `compareDocumentPosition`. Решение со `Set` работает и для любых деревьев со ссылкой на родителя, а не только для DOM.

Сложность: O(h) времени и памяти, h — глубина дерева.
:::

### 2. Плоский список в дерево и обратно · средне

Сервер отдаёт комментарии плоским списком `{ id, parentId, text }`, где у корневых `parentId === null`. Порядок произвольный: ребёнок может прийти раньше родителя. Постройте дерево `{ ...item, children }`, сохранив исходный порядок среди братьев. Затем напишите обратную функцию — плоский список с глубиной для отрисовки.

::: details Решение и разбор
Первый проход создаёт узлы по `id`, второй прикрепляет каждый узел к родителю. Два прохода снимают зависимость от порядка входа.

```js
function toTree(items) {
  const byId = new Map(items.map((item) => [item.id, { ...item, children: [] }]));
  const roots = [];
  for (const item of items) {
    const node = byId.get(item.id);
    const parent = item.parentId === null ? undefined : byId.get(item.parentId);
    (parent ? parent.children : roots).push(node); // orphans become roots
  }
  return roots;
}

function toFlat(roots) {
  const result = [];
  const stack = roots.map((node) => [node, 0]).reverse();
  while (stack.length) {
    const [node, depth] = stack.pop();
    const { children, ...rest } = node;
    result.push({ ...rest, depth });
    for (let i = children.length - 1; i >= 0; i--) stack.push([children[i], depth + 1]);
  }
  return result;
}
```

Вопросы, которые стоит задать: что делать с сиротой, чей родитель удалён (здесь она становится корнем, вариант — отбросить), и с дубликатами `id`. Цикл в данных (`a.parentId = b`, `b.parentId = a`) даёт узлы, недостижимые из корней: `toTree` не зависнет, но потеряет их. Обнаружить это можно, сравнив размер `toFlat` с `items.length`. `toFlat` итеративный, поэтому ветка ответов глубиной 100 000 его не уронит. Для свёрнутых веток в виртуальном списке потомков свёрнутого узла просто не кладут в стек.

Сложность: O(n) времени и памяти в обе стороны.
:::

### 3. Кратчайший путь в лабиринте · средне

Лабиринт — массив строк, `#` — стена, `.` — проход, `S` — старт, `E` — выход. Ходить можно на четыре стороны. Верните минимальное число шагов или `-1`.

```js
shortestSteps(['S.#', '.##', '..E']); // 4
```

::: details Решение и разбор
Сетка — неявный невзвешенный граф, и BFS находит кратчайший путь. Клетка кодируется числом `r * cols + c`, расстояния лежат в `Int32Array`, где `-1` означает «не посещена».

```js
function shortestSteps(grid) {
  const rows = grid.length;
  const cols = grid[0]?.length ?? 0;
  const dist = new Int32Array(rows * cols).fill(-1);
  const queue = [];
  for (let r = 0; r < rows; r++) {
    const c = grid[r].indexOf('S');
    if (c !== -1) { dist[r * cols + c] = 0; queue.push(r * cols + c); }
  }
  const moves = [[1, 0], [-1, 0], [0, 1], [0, -1]];
  for (let head = 0; head < queue.length; head++) {
    const cell = queue[head];
    const r = Math.floor(cell / cols);
    const c = cell % cols;
    if (grid[r][c] === 'E') return dist[cell];
    for (const [dr, dc] of moves) {
      const nr = r + dr;
      const nc = c + dc;
      if (nr < 0 || nr >= rows || nc < 0 || nc >= cols || grid[nr][nc] === '#') continue;
      const next = nr * cols + nc;
      if (dist[next] === -1) { dist[next] = dist[cell] + 1; queue.push(next); }
    }
  }
  return -1;
}
```

Проверка границ идёт раньше обращения к `grid[nr]`: `grid[-1][c]` бросит `TypeError`. Отметка `dist` при постановке в очередь гарантирует, что каждая клетка попадает в неё один раз. Если стартов несколько, все кладутся в очередь с расстоянием 0 (multi-source BFS): так за один проход считают расстояние до ближайшего выхода из каждой клетки. Если у клеток разная стоимость (болото дороже дороги), нужен Дейкстра. DFS здесь ошибочен: первый найденный путь не обязательно короче.

Сложность: O(rows · cols) времени и памяти.
:::

### 4. Порядок сборки пакетов · средне

Дан объект зависимостей `{ app: ['ui', 'utils'], ui: ['utils'], utils: [] }`. Верните порядок сборки, в котором каждый пакет собирается после своих зависимостей. Если зависимости циклические, бросьте ошибку с перечнем пакетов в цикле. Неизвестная зависимость — тоже ошибка.

::: details Решение и разбор
Алгоритм Кана. Ребро идёт от зависимости к зависящему пакету, входящая степень — число неразрешённых зависимостей пакета.

```js
function buildOrder(deps) {
  const inDegree = new Map();
  const dependents = new Map();
  for (const [pkg, list] of Object.entries(deps)) {
    inDegree.set(pkg, list.length);
    if (!dependents.has(pkg)) dependents.set(pkg, []);
    for (const dep of list) {
      if (!Object.hasOwn(deps, dep)) throw new Error(`Unknown dependency: ${pkg} -> ${dep}`);
      if (!dependents.has(dep)) dependents.set(dep, []);
      dependents.get(dep).push(pkg);
    }
  }
  const queue = [...inDegree.keys()].filter((pkg) => inDegree.get(pkg) === 0);
  for (let head = 0; head < queue.length; head++) {
    for (const next of dependents.get(queue[head])) {
      inDegree.set(next, inDegree.get(next) - 1);
      if (inDegree.get(next) === 0) queue.push(next);
    }
  }
  if (queue.length < inDegree.size) {
    const stuck = [...inDegree.keys()].filter((pkg) => inDegree.get(pkg) > 0);
    throw new Error(`Circular dependency among: ${stuck.join(', ')}`);
  }
  return queue;
}
```

`buildOrder({ app: ['ui', 'utils'], ui: ['utils'], utils: [] })` → `['utils', 'ui', 'app']`. Пакеты, у которых входящая степень обнулилась на одном шаге, можно собирать параллельно — та же идея, что у параллельного запуска задач в Turborepo и Nx. Оговорка в сообщении об ошибке: «застрявшие» пакеты — это цикл **и всё, что от него зависит**. Чтобы выдать сам цикл (`a → b → c → a`), нужен DFS с тремя цветами: при ребре в серую вершину цикл — часть текущего пути от неё до вершины, на которой стоим. Повторяющаяся зависимость в списке (`['ui', 'ui']`) не ломает алгоритм: степень и обратные рёбра считаются одинаково.

Сложность: O(V + E) времени и памяти.
:::

### 5. Сериализация двоичного дерева · сложно

Напишите `serialize(root)` и `deserialize(str)` для двоичного дерева `{ value, left, right }` с числовыми значениями. `deserialize(serialize(t))` должен восстанавливать ту же форму, а не только тот же набор значений. Деревья могут быть вырожденными глубиной 10⁵.

::: details Решение и разбор
Одного pre-order недостаточно: `1 → left 2` и `1 → right 2` дают одинаковую последовательность. Форму сохраняют маркеры пустых детей: pre-order с `#` на месте `null`. Обе функции итеративные из-за требования к глубине.

```js
function serialize(root) {
  const out = [];
  const stack = [root];
  while (stack.length) {
    const node = stack.pop();
    if (!node) { out.push('#'); continue; }
    out.push(String(node.value));
    stack.push(node.right, node.left); // left is processed first
  }
  return out.join(',');
}

function deserialize(str) {
  const tokens = str.split(',');
  const make = (t) => (t === '#' ? null : { value: Number(t), left: null, right: null });
  const root = make(tokens[0]);
  const stack = root ? [[root, 'left']] : []; // [parent, side still to fill]
  for (let i = 1; i < tokens.length; i++) {
    const top = stack.at(-1);
    const [parent, side] = top;
    const node = make(tokens[i]);
    parent[side] = node;
    if (side === 'left') top[1] = 'right';
    else stack.pop(); // both children are filled
    if (node) stack.push([node, 'left']);
  }
  return root;
}
```

`deserialize` — стек «родитель и сторона, которую заполнять следующей». Каждый токен — следующий ребёнок верхнего узла, сначала левый, потом правый. Новый непустой узел становится вершиной стека, потому что в pre-order его поддерево идёт сразу за ним. Решение проверено круговым тестом на случайных деревьях, на пустом дереве (`'#'`) и на цепочках глубиной 10⁵ влево и вправо, где рекурсивная версия падает с `RangeError`. Значения через `String` и `Number` — это контракт задачи. Для строк понадобилось бы экранирование разделителя, и проще отдать `JSON.stringify` массив токенов. Альтернатива — BFS по уровням, как в формате LeetCode: она тоже итеративна, но для вырожденного дерева хранит маркеры каждого уровня.

Сложность: O(n) времени и памяти; строка — 2n + 1 токенов.
:::
